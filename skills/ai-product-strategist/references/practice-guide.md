# Evidence and experiment decisions

## Frame the opportunity
Describe the user task, frequency, current workaround, consequence of failure and evidence source. An enthusiastic request for an agent is a solution hypothesis. Compare it with the simplest viable non-AI or assisted workflow before proposing autonomy.

## Filled experiment
For support triage, measure current handling time and misroutes on a representative queue. Pilot AI suggestions with human confirmation. Select a target reduction in handling time and maximum harmful misroute rate with the decision owner before running the pilot. Include the cost of review and escalation in the comparison.

## Evidence map
Separate observed facts, user statements, assumptions and projections. Name what would reject the value hypothesis. Missing baseline data calls for a measurement plan, not an invented percentage.

## Prioritization
Link each proposed milestone to the decision it answers and the user outcome it supports. Consider failure cost, reversibility, adoption and operating expense, not only model capability. A regulated or high-impact context needs concrete product review obligations; avoid adding speculative process to unrelated low-risk work.
